# Fixture datasets (`data/fixtures/`)

Recorded third-party API responses used by the discovery connectors when
`FIXTURES=1` is set (or when an API key is missing). Replay is **transparent**:
the fixture player (`src/lib/connectors/fixtures.ts`) adapts these recorded
datasets to the exact raw API shapes the connectors parse, so rehearsals
(`FIXTURES=1`) and the live demo exercise identical logic.

> Canonical dataset: `v2.0-advanced` (3 target personas), generated by
> `generate_advanced_dataset.py` and validated by `validate_dataset.py`
> (repo root). Both scripts are owned by the dataset specialist.

## `serper_response.json` — recorded Serper searches

```json
{
  "searches": [
    { "person_id": "person_1", "query": "\"rahul.kumar@abc-tech.in\"", "results": [ { "title", "url", "snippet", "source_id", "discovered_at", "confidence", "evidence_tier" } ] }
  ],
  "summary": { "...": "..." }
}
```

- The player resolves the recorded search for a planned query: **exact match
  first, then containment fallback**, mapped into the raw organic shape
  (`title/link/snippet/date/position`) that `mapSerperResponse()` consumes.
- `searches[0..2]` are the dataset's originals (one per persona);
  `searches[3:]` were added by the connector work to cover the planner's full
  query set (username, name+email, `filetype:pdf`, name+org — including a
  Radaris listing so the broker matcher has something to flag).

## `exposedornot_response.json` — recorded breach records

Per-person breach records with pre-classified metadata:

```json
{
  "breaches": [
    { "person_id": "person_1", "email": "rahul.kumar@abc-tech.in", "breach_name": "CodeDump-2024",
      "exposure_type": "CREDENTIAL_EXPOSURE", "severity": "high", "passwords_included": true, ... }
  ]
}
```

The player synthesizes the two raw API payloads from these records
(`checkEmail` breach-name list + `breach-analytics` metrics), keeping
`exposedOrNot.ts`'s parsing as the single source of truth for live and
replayed data. `passwords_included: true` drives the `CREDENTIAL_EXPOSURE`
signal via exposed data classes.

An unknown email maps to `{ "Error": "Not found" }` — a clean OK result, **not**
a source failure (the API answered).

## Ownership & conventions

- `data/brokers.json` (59 entries: curated catalog + connector-seeded extras)
  and `data/eval/` belong to the dataset owner; the broker matcher accepts a
  bare array or `{ "brokers": [...] }`.
- The fixture player (`src/lib/connectors/fixtures.ts`) and connector
  interfaces are owned by Dev-2. When extending fixtures, note that:
  - no stored result field may embed raw identifiers beyond what a real API
    response contains;
  - recorded queries should be exact planned queries (`buildTargetedQueries()`)
    so the exact-match path in the player hits first.
